# Framework — Framing-Check Canvas for Floor Policy and Call Design

Use in workshop or print for the floor. Run one canvas per risky call or policy announcement before you send it.

## 1. The call (one sentence)

What am I about to announce or decide, right now?

## 2. Frame audit

| Question | Answer | Why |
| --- | --- | --- |
| Is this worded around a loss ("avoid losing...") or a gain ("protect/earn...")? | | |
| Is a specific vivid, recent incident driving today's emotional read? | | |
| Would the decision change if I stated the identical facts the opposite way? | | |

## 3. Reframe test

Write the same facts as a loss, then as a gain, in one sentence each:

- Loss version:
- Gain version:
- Does the decision hold up under both? If not, which one matches the actual facts, not just the fastest yes?

## 4. Route decision

- **Reframe test passes, no vivid incident driving it:** Proceed with the frame that matches the facts. Note it and move on.
- **One trigger present (loss language or a vivid incident):** Check the actual pattern (log, defect rate, prior flags) before sending the announcement.
- **Reframe test fails, or two triggers present:** Hold the announcement; resolve which frame is honest before it goes to the team.

## 5. One-off or standing policy?

Does this type of call repeat often enough that it should be a fixed rule, decided once and applied the same way every time, rather than reframed fresh under each shift's pressure?

## 6. Visibility

Where does the team see the frame you chose and why (board, radio call, log entry)?

## 8. After-action note

Which frame did you actually use, and did it match the facts or just get the fastest agreement? Add one line to the shift log either way.
