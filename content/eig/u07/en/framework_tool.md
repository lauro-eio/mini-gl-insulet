# Framework — Embed Map: Three Touchpoints Where the Skill Sticks or Fades

Use in workshop or print for the floor. Run this once per touchpoint you want to build or repair.

## 1. The touchpoint (pick one)

Which moment am I embedding the skill into: new-hire onboarding, pre-shift huddle coaching, or a peer check after an incident?

## 2. Current state check

| Question | Yes/No | Why |
| --- | --- | --- |
| Does this touchpoint currently happen at all, even informally? | | |
| Does it happen the same way whether or not I am on shift? | | |
| Would a new hire or teammate describe it as normal, not remedial? | | |

## 3. Design decision

- **Not happening at all:** Design the smallest version that could run this week (a two-minute check-in, one modeled sentence in the huddle, one opt-in peer conversation).
- **Happening but depends on me:** Name a second owner and hand off one instance this month.
- **Happening and owned:** Set a review date and check whether it is still landing as intended.

## 4. Build it (fill in for the touchpoint you picked)

1. What exactly happens, in one sentence (who says or does what, and when)?
2. Who owns it if I am off-shift?
3. How does a new hire or teammate learn this is normal, not a special program?

## 5. Visibility

Where does the team see this touchpoint happen—so it reads as standard practice, not a one-time announcement?

## 6. Guardrail

What would cause this touchpoint to quietly stop during the next busy stretch, and what protects it when that happens?

## 7. After-action note

One month from now: did this touchpoint run as designed, drift, or disappear? Add one line to your log either way.
